# GB28181 模块 — 后端 ↔ 流媒体(媒体组) 接口契约 v0.1

> 作者:后端组(契约发起方)。本文件定义 easySVA 后端与流媒体服务器(ZLM/国标网关)
> 之间的 GB28181 对接约定。媒体组按此实现后,只需把数据库开关置 1,后端即全量生效,
> 无需再改后端代码。

## 0. 总体约定

- 国标设备采用 **“通道级导入”**:ZLM 上每个可点播通道 = `h_device` 一条记录,
  `ape_id = 通道唯一标识(channelId)`。
- RTSP 与 GB28181 统一:设备“出流”后都挂在 ZLM 上,统一走既有
  `rtsp://{zlm}:9994/{app}/{stream}` / `ws://{zlm}:9992/{app}/{stream}.live.flv` 形式,
  布控/AI 链路**完全不变**(满足课程文档“布控任务逻辑不变,国标设备和 RTSP 设备统一对待”)。
- 后端只负责:设备表管理、一键导入、状态同步、预览 URL 编排、向分析器下发;SIP 注册、
  RTP 接收、GB 通道 REST 由媒体组在 ZLM(或其网关)实现。

## 1. 数据库开关(已就绪)

| 位置 | 字段 | 说明 |
|---|---|---|
| `zlm_server` | `gb28181_enabled` tinyint default 0 | 媒体能力就绪后置 1 |
| `zlm_server` | `gb_sip_port` int | SIP 端口(默认 5060),供展示 |
| `h_device` | `device_type` RTSP/GB28181 | 设备类型 |
| `h_device` | `gb_device_id` / `gb_platform_id` | 国标设备/平台编码 |

开启: `UPDATE zlm_server SET gb28181_enabled=1, gb_sip_port=5060 WHERE id=1;`

## 2. 媒体组需在 ZLM(或国标网关)实现的 REST 契约

base = `http://{zlm_server.host}:{zlm_server.api_port}`(当前为 9992),所有调用带
`?secret={zlm_server.secret}`。

### 2.1 列出已注册国标通道
`GET {base}/index/api/gb/listChannels`
响应(统一信封):
```json
{ "code": 0, "msg": "ok",
  "data": { "channels": [
    { "channelId": "34020000001320000001",   // 通道唯一ID(将作为 h_device.ape_id)
      "channelName": "车间大门",
      "gbDeviceId": "34020000001320000001",  // 设备国标编码(20位)
      "gbPlatformId": "34020000002000000001",// 平台国标编码(可选)
      "online": "1",                          // "1"/"0"
      "ip": "192.168.1.10",                   // 可选
      "manufacturer": "hikvision" } ] } }
```
- 若某项不存在请省略键;后端解析兼容 camelCase 与下划线两种拼写。
- 至少提供 `channelId`;其余可为 null。
- 未实现/内部错误时返回 `{code: 非0, msg: ...}`(后端转为友好提示)。

### 2.2 点播某通道(可选,后端 `live/gb/{apeId}` 与“启动监控”会调用)
`GET {base}/index/api/gb/play?channelId=34020000001320000001`
响应:`{ "code": 0, "data": { "playUrl": "ws://{host}:9992/gb/34020000001320000001.live.flv" } }`
- 后端拿到 `playUrl` 后写入 `h_device.play_url`;拿不到时按契约默认值
  `ws://{host}:9992/{app}/{apeId}.live.flv` 兜底。

### 2.3 停止点播(可选)
`GET {base}/index/api/gb/bye?channelId=...`

### 2.4 上下线主动回调(媒体组尽量支持;后端也提供轮询兜底)
`POST http://{backend}:9114/waring/device/gb/notify`(已放行免登录)
```json
{ "channelId": "34020000001320000001", "online": "1",
  "event": "register" }          // register/unregister/keepalive
```
- 后端回调更新 `h_device.is_online`(1/0)。

## 3. 后端已提供接口(供前端组调用)

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/waring/device/gb/remote-channels` | 预览 ZLM 已注册国标通道(未启用→友好错误提示) |
| POST | `/waring/device/gb/import` | 一键导入/同步:通道→h_device(幂等;返回 imported/updated/online/offline/errors) |
| POST | `/waring/device/gb/status/sync` | 手动触发上下线状态同步(轮询 2.1) |
| GET | `/waring/device/live/gb/{apeId}` | 国标设备实时播放地址 |
| GET/POST/PUT/DELETE | `/waring/device/**` | 通用设备 CRUD(已支持 `device_type` 过滤/新增字段) |
| POST | `/waring/device/monitor/{apeId}/start|stop` | 启停监控(GB 设备自动走点播契约) |

## 4. 对布控/AI 链路的说明

- 布控下发载荷(`POST {sva_server}:9993/api/control/add`)**新增只读标注字段**:
  `sourceType`/`deviceType` = `GB28181 | RTSP`;`streamUrl` 等既有字段语义不变。
- AI 组(sva-server)无需为 GB 单开逻辑:只要国标通道在 ZLM 上按既有
  app/stream 形式出流即可复用整条“解码→推理→告警”链路。

## 5. 验收 checklist(媒体组)

- [ ] ZLM 启动 GB28181 SIP(5060),IPC 可注册
- [ ] `/index/api/gb/listChannels` 返回上述 JSON(通道含真实 channelId/在线状态)
- [ ] `gb28181_enabled=1` 后,后端 `/gb/import` 能导入;`/live/gb/{apeId}` 能返回播放地址
- [ ] 设备断电后 `online=0` 能同步/回调到设备表
