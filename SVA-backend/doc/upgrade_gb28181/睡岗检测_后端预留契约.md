# 睡岗检测 — 后端预留(数据/载荷契约)说明 v0.1

> 面向 AI 算法组(sva-server)与前端组。睡岗的核心(姿态模型推理)由算法组在
> SVA-server 实现;本文件描述后端已预留/约定的部分,保证全链路可直接打通。

## 1. 已做的后端/数据库预留

### 1.1 算法元数据(av_algorithm)
```sql
code      = on_yolopose_sleep
name      = 睡岗检测(姿态关键点)
object_count = 0          -- 睡岗无需“目标物类别”
object_str = ''           -- 同上
state     = 0
```
- 前端“布控/规则”下拉将能看到该算法(需要前端组读取 av_algorithm 列表即可,后端已有接口)。
- 提醒:若算法组希望用其它 code,请统一修改本行 + SVA-server 端识别逻辑(建议加注释说明出处)。

### 1.2 布控算法参数(可配置阈值)
`deployment_task_algorithm` 新增列 `params_json text`(已建)。
示例(睡岗):`{"headPitchDeg":30,"leanAngleDeg":15,"durationSec":5,"frameSkip":1}`
- 前端组:布控规则页对 `on_yolopose_sleep` 显示“角度/持续时间”输入,写入该 JSON。
- 后端:随布控下发载荷**原样透传**(见 2.1)。

### 1.3 告警类型
后端告警落库(h_waring)不限定 alarm_type 字符串;算法组上报的告警类型建议:
`alarm_type = sleep`, `alarm_type_name = 睡岗告警`(可与前端组统一字典后修订)。

## 2. 下发载荷(启动布控 → 分析器)

`POST {sva_server}:9993/api/control/add` 载荷与旧版兼容,新增/预留要点:

```jsonc
{
  "code": "<deploymentId>",
  "sourceType": "GB28181 | RTSP",        // 新增:设备来源
  "deviceType": "GB28181 | RTSP",
  "streamCode"/"streamApp"/"streamName"/"streamUrl": "…",  // 原有,不变
  "algorithmCode": "on_yolopose_sleep",
  "objectCodes": [],                     // 姿态类允许为空(后端已放开)
  "algorithmTasks": [
    {
      "algorithmCode": "on_yolopose_sleep",
      "detectFps": 5,
      "scoreThreshold": 0.5,
      "params": { "headPitchDeg":30, "durationSec":5 },  // 预留:算法自定义参数(JSON对象或原文)
      "paramsJson": "{\"headPitchDeg\":30,...}"
    }
  ]
}
```

## 3. 告警上行(分析器 → 后端,与旧版一致)

- 截图/短视频:写入 `{uploadDir}/alarm/...`(= /var/www/SVA-web/upload/alarm),走既有 nginx `/alarm/`。
- 摘要上报:复用既有白名单接口
  `POST /waring/waring/addFromSvaSimple`(字段含 alarm_type/device_id/picture_url/video_url 等,建议 sleep)。
- 媒体绑定:分析器调用 `{sva_server}:9993/api/alarm/bind-media` 把告警与截图/片段绑定(既有逻辑)。
