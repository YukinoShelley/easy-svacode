# P0 链路预验证 · 部署与验证手册

> **目标**：在目标机上把「GB28181 模拟设备 → WVP(SIP网关) → ZLM(媒体)」整条链路跑通，验证"设备注册/目录/INVITE/出流"，**不涉及业务代码改动**。
> **通过标准（P0 PASS）**：ZLM 中出现 `live/{设备通道号}` 国标流，`getMediaInfo` 返回 code=0 且能被 ffmpeg 拉到帧。

---

## 0. 前提（目标机需具备）

| 依赖 | 要求 | 说明 |
|------|------|------|
| JDK | 8+（本机 17 可用） | WVP 是 Java |
| Maven | 任意 | 打包 WVP |
| MySQL/MariaDB | 任意 | WVP 独立库 `wvp` |
| Redis | 任意 | WVP 依赖缓存 |
| Node.js | 有则编译前端控制台 | 若 WVP 版本需自建 web |
| ZLM | 现有(`10.122.205.66`) | 端口 http `9992`/rtsp `9994`/rtmp `9995`，secret `V3522025zlm0aA9ajn7UiOWi`，RTP段 `30002-40000` |
| 端口空闲 | `5060`(SIP)、`18080`(WVP Web) | |

> 若用**专用机**，需能从该机访问 ZLM 的 http/rtsp/rtp；国标设备需能反连 SIP(5060) 与 RTP 段。

## 1. 克隆 WVP 并初始化数据库

```bash
cd $HOME
git clone https://gitee.com/pan648540858/wvp-GB28181-pro.git

# 建独立库

#   sql/wvp/…*.sql  —— 请按仓库目录找到并导入

```

## 3. 配置 `application-dev.yml`（关键项，已对齐本机 ZLM）

```yaml
server:
  port: 18080
spring:
  datasource:
    url: jdbc:mysql://127.0.0.1:3306/wvp?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&useSSL=false
    username: root
    password: 改我
  redis:
    host: 127.0.0.1
    port: 6379
    database: 0
sip:
  id: 34020000002000000001      # 平台国标编码(20位)
  domain: 3402000000
  ip: 10.122.205.66             # SIP 对外地址(设备需能反连)
  port: 5060
  password: 12345678
media:
  - id: default-zlm
    ip: 10.122.205.66           # ZLM 地址(用于 rtp/http)
    stream-ip: 10.122.205.66    # 对外推流地址
    http-port: 9992             # 与 ZLM [http]
    rtsp-port: 9994             # 与 ZLM [rtsp]
    rtmp-port: 9995             # 与 ZLM [rtmp]
    secret: V3522025zlm0aA9ajn7UiOWi
    rtp:
      enable: true
      port-range: "30002-40000" # 与 ZLM [rtp] 一致
user-settings:
  # 以实际版本为准：默认管理员、注册码、保活等
```

> ⚠️ `media.ip`(收 RTP) 与 `stream-ip`(对外) 的区别：设备推送 RTP 到 `ip`；前端拉流走 `stream-ip`/`http-port`。若设备与 ZLM 在同一内网，二者都填 `10.122.205.66`。

## 6. 点播（INVITE）→ 断言出流

在 WVP Web 上点"播放/点播"该通道，然后在能访问 ZLM 的机器执行：

```bash
# 关键判定：ZLM 是否出现国标流（code=0 即通）
curl -s "http://10.122.205.66:9992/index/api/getMediaInfo?secret=V3522025zlm0aA9ajn7UiOWi&vhost=__defaultVhost__&app=live&schema=rtsp&stream=34020000001320000001" \
  | python3 -c "import sys,json;d=json.load(sys.stdin);print('code:',d.get('code'),'alive:',d.get('aliveSecond','-'))"

# 帧级验证
ffmpeg -rtsp_transport tcp -i rtsp://10.122.205.66:9994/live/34020000001320000001 -t 3 -f null - 2>&1 | grep -E "frame=" | tail -1
```

也可以用 `gb28181-poc/04_verify_poc.sh`（设置 `CHANNEL` 为设备通道号后执行）。

## 8. 常见坑（提前避雷）

1. **`media.ip` 错了** → INVITE 后设备把 RTP 推到错误地址，ZLM 无流。确认与设备可达地址一致。
2. **RTP 端口段不一致** → ZLM `[rtp] port_range` 与 WVP `rtp.port-range` 必须一致（都建议 `30002-40000`）。
3. **secret 不匹配** → WVP 调 ZLM API 失败。用 `zlm_server` 表的 secret。
4. **SIP digest/保活超时** → 设备注册后很快变成离线。按标准调 keepalive 与密码。
5. **NAT/公网** → 设备从外网注册时，`sip.ip`/`stream-ip` 需公网可达地址，否则反连失败。
6. **web 控制台没构建** → 打不开 18080 界面。确认 `web` 产物在 `wvp-pro/src/main/resources/static`。
7. **初始化 SQL 没导入** → WVP 启动报表不存在。按仓库 SQL 导入 `wvp` 库。

## P0 实测结论（2026-09-03，已实证）

| 项 | 结果 | 关键证据 |
|----|------|---------|
| GB28181 信令 | ✅ 全通 | 模拟设备→WVP：注册→401摘要→认证→上线→目录(1通道) |
| ZLM 解 PS 媒体 | ✅ 成立 | 设备推的 PS 被 ZLM 判定 `judged to be PS`（`GB28181Process`） |
| PS 推送链路 | ✅ 已实现 | `ps_rtp.py`(PS-over-RTP打包器) + `ffps.sh`(client包装) 生效，ffmpeg 持续产 PS |
| **唯一卡点** | ⚠️ WVP on_publish 鉴权 | ZLM 调 `on_publish`→WVP(`:18080/index/hook/on_publish`)返回 `auth failed`，把已识别为 PS 的流拒掉 |

**结论**：P0 两个核心可行性问题（信令 + ZLM 解 PS 媒体）已证明可行；剩余为 **WVP↔ZLM 推流鉴权集成**项，属于任务一媒体接入集成工作。真实国标摄像头（原生 PS）接入，WVP 正确放行后即可出流。

**关键产物**：`ps_rtp.py`、`ffps.sh`、`gb28181-client`(已切 PS 推流)、WVP(JDK21) 已在本机部署联调。

**备注（排障经验）**：
- WVP 点播"在途"卡死 → 由残留的 redis `VMP_SIP_INVITE_SESSION_INFO`（SsrcTransaction）导致；清该键 + 重启 WVP（且务必确保**只有一个 WVP 进程**，旧进程占端口会导致新配置不生效）。
- WVP API 登录：`GET /api/user/login?username=&password=<md5(密码)>`，返回 `data.accessToken`；接口鉴权用请求头 **`access-token:`**（不是 Bearer）。
- 设备推流必须 **PS over RTP**（`GB28181Process` 只认 PS，不认 rtp_mpegts/TS）。
