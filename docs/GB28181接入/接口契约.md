# 接口契约（任务一 / 任务二 共同基线）

> **性质**：任务一（GB28181 国标接入）与任务二（睡岗算法）的**共同接口基线**。所有涉及接口的改动，必须以本契约为准——**只增字段，不改/删既有字段名**。
> 文中标注 **【实测】** 的均为对当前运行系统实际调用返回的真实样本（可直接用于前端联调/断言）；未标注的 GB28181 专属字段为**设计态**，在 WVP 接入后按本格式返回。

## 1. 设备（h_device）字段定义

### 1.1 现有字段（实测样本，`/waring/device/cam979722`）

```json
{
  "ape_id": "cam979722",
  "name": "11",
  "stream_source_type": "DIRECT",
  "direct_source_url": "http://tv.byr.cn/.../index.m3u8",
  "play_url": "ws://10.122.205.66:9992/live/cam979722.live.flv",
  "zlm_proxy_key": "__defaultVhost__/live/cam979722",
  "ip_addr": null, "port": null,
  "org_index": "10", "org_name": "总公司",
  "is_online": null,
  "monitor_status": "RUNNING",
  "zlm_server_id": 1, "sva_server_id": 1
}
```

### 1.2 任务一新增字段（设计态，`h_device` 追加）

| 字段 | 类型 | 说明 |
|------|------|------|
| `device_type` | string | `RTSP` / `GB28181`，区分接入方式（前端据此展示不同交互） |
| `gb_id` | string | 国标设备编码（20 位，如 `34020000001320000001`）；RTSP 可为空 |
| `gb_domain` | string | 国标 SIP 域（如 `3402000000`） |
| `gb_password` | string | 国标 SIP 摘要认证密码（敏感，后端存，**不返回前端明文**） |
| `channel_count` | int | 通道/摄像机数量 |
| `status` | string | `ONLINE` / `OFFLINE`（由 WVP 事件驱动更新） |
| `sip_server` | string | 所属 SIP 平台（WVP）标识 |

> **前端约定**：`device_type` 驱动界面分支（RTSP=填源地址；GB28181=填国标编码/域）；`status`(若空则看 `is_online`) 驱动在线/离线徽标；`play_url` 直接用于预览。

**RTSP 设备示例**
```json
{ "device_type": "RTSP", "ape_id": "rtsp-cam-01", "name": "门口球机",
  "direct_source_url": "rtsp://192.168.1.20:554/stream1", "status": "ONLINE",
  "play_url": "ws://10.122.205.66:9992/live/rtsp-cam-01.live.flv" }
```
**GB28181 设备示例**
```json
{ "device_type": "GB28181", "ape_id": "34020000001320000001", "name": "国标枪机01",
  "gb_id": "34020000001320000001", "gb_domain": "3402000000",
  "channel_count": 1, "status": "ONLINE", "ip_addr": "192.168.1.30" }
```

## 2. 国标流 URL 约定（任务一定义，分析器/任务二无需感知）

```
拉流(给分析器):   rtsp://{zlm_host}:9994/live/{gb_id}
预览(给前端):     ws://{zlm_host}:9992/live/{gb_id}.live.flv   (HTTP-FLV over WS)
```

- 国标设备经 WVP 注册、INVITE 后，ZLM 解复用出 `live/{gb_id}`，与现有 RTSP 设备**同路径** → 分析器零改动接入。

---

## 3. 设备状态事件契约（WVP/ZLM → 后端 → 前端）

| 事件 | 触发 | 后端行为 | 前端可见 |
|------|------|----------|---------|
| `DEVICE_REGISTER` | 设备注册成功 | `h_device.status=ONLINE`；channel 同步 | 列表"在线"徽标 |
| `DEVICE_KEEPALIVE` | MESSAGE 保活 | 刷新在线时间/判定在线 | 不变 |
| `DEVICE_OFFLINE` | 注册过期/断连 | `h_device.status=OFFLINE` | "离线"徽标 |
| `DEVICE_PLAY`(INVITE成功) | 点播 | 生成 `play_url`/`stream_url` | 可预览 |

> 状态更新以后端为权威；`monitor_status`（启动/停止监控）与 `status`(在线) 两个概念分开。

## 6. 前端实现要点（交代清楚）

1. **设备页**：用 `device_type` 区分两套表单/展示；用 `status`/`is_online` 显示在线徽标；预览用 `play_url`（或 `monitor/{apeId}/preview` 返回的 `playUrl`）。
2. **国标设备的"预览"**：先从 `monitor/{apeId}/preview` 取 `playUrl`；若为空可先调 `monitor/{apeId}/start` 启动监控后再取。
3. **布控"详情"实时画面**：调 `live-output` 拿 `algorithmStreamUrl`；**若为空（无推流）则回退用设备原始预览**——这是前端**必须**处理的分支（已经实测到无推流返回空 data）。
4. **播放器**：地址是 **ws-flv**（`…/live/{x}.live.flv`），需用支持 WS-FLV/HTTP-FLV 的播放器（如 flv.js / 结合 WebSocket）。
5. **字段命名兼容**：前后端字段有 `camelCase`（接口返回）与 `snake_case`（部分老数据）两套，前端读取时用 `getFieldValue(obj,'camel','snake')` 兜底（现有前端 `index.vue` 已这样处理）。
