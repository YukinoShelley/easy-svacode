# 流媒体侧 · GB28181 接入能力与接口契约（角色1·流媒体开发）

> 职责：SVA-mediaServer（ZLMediaKit）的 GB28181 接入能力开发。
> 后端/前端/分析器只负责**提供/对接接口**；本契约定义流媒体侧**对外提供的接口**与**需要其它角色提供的接口**。
> 数据取自本机 P0 实测（2026-09-03），可信。

---

## 1. 流媒体侧定位

- 组件：**SVA-mediaServer（ZLMediaKit，git 046aaa3 / 2024-05-01，build 2024-08-22）**
- 已具备能力（二进制含）：`mediakit::GB28181Process::inputRtp` —— **接 GB28181 的 PS-over-RTP 并解复用为流**
- 端口：`[http] 9992 · [rtsp] 9994 · [rtmp] 9995 · [rtp] port_range 30002-40000`
- secret：`V3522025zlm0aA9ajn7UiOWi`

## 2. 总体数据流

```
国标摄像头(SIP) ──REGISTER/INVITE──▶ SIP平台(本机以 WVP 代研) 
        │
        └──(INVITE 应答 SDP: c/m 指向 ZLM 收流口 + SSRC)──▶ 设备把 PS/RTP 推到 ZLM:30002-40000
                                                                  │
                                        GB28181Process 解 PS ──▶ live/{streamId}
                                                                  │
            前端播放 ◀── ws://zlm:9992/live/{id}.live.flv      分析器拉流 ◀── rtsp://zlm:9994/live/{id}
```

> **关键点**：ZLM 只负责**媒体**（收 PS-RTP → 出 live 流）；**SIP 信令**（注册/保活/INVITE）由 SIP 平台承担（WVP）。流媒体角色需要与后端/SIP 平台能对接（见 §4/§5）。

## 3. 流命名与播放 URL 约定（对外接口 · 分析器/前端消费）

| 类型 | 流名 | 拉流给分析器 | 播放给前端 |
|------|------|------------|-----------|
| GB28181 通道 | `live/{deviceChannelId}`（国标通道编码） | `rtsp://{zlm}:9994/live/{id}` | `ws://{zlm}:9992/live/{id}.live.flv` |
| RTSP/DIRECT 设备 | `live/{deviceId}` | 同上 | 同上 |
| 分析输出(推流) | `analyzer/{deploymentId}` | 回注/ZLM | `ws://{zlm}:9992/analyzer/{id}.live.flv` |

- `{zlm}` 通常为 `10.122.205.66`；同机也可 `rtsp://127.0.0.1:9994/...`。
- 前端需用 **HTTP-FLV over WebSocket**（`.live.flv`）或 `rtsp`（用 flv.js/WebSocket + 相应播放器）。

## 4. mediaServer 对外提供的接口（供后端/前端调用）

### 4.1 ZLM HTTP API（`http://{zlm}:9992/index/api/...`，需带 `secret`）
| 接口 | 用途 |
|------|------|
| `openRtpServer` | 开启一个 RTP 收流口（国标 INVITE 时由 SIP 平台/后端调用），返回端口；`stream_id` 决定 `live/{stream_id}` |
| `closeRtpServer` | 关闭 RTP 收流口 |
| `getMediaList` / `getMediaInfo` | 查询当前流（判断国标流是否上线/在线） |
| `addStreamProxy` / `delStreamProxy` | 主动拉取 RTSP/HLS（用于 DIRECT 设备、测试源） |
| `getServerConfig` | 获取节点配置/secret 核对 |

<details><summary>调用示例（getMediaInfo 判定国标流是否上线）</summary>

```bash
curl -s "http://10.122.205.66:9992/index/api/getMediaInfo?secret=V3522025zlm0aA9ajn7UiOWi&vhost=__defaultVhost__&app=live&schema=rtsp&stream=34020000001320000001"
# code=0 → 流已上线（P0 判定标准）
```
</details>

### 4.2 ZLM → 后端 的事件 hook（mediaServer 通知后端）
配置于 `[hook]`（本机已指向 WVP `:18080`，正式可指后端）：`on_publish`、`on_stream_changed`、`on_stream_none_reader`、`on_rtp_server_timeout`。
- 后端据此同步**设备/流在线离线状态**（对接前端在线徽标、分析器启动时机）。

## 5. 流媒体侧 需要 其它角色 提供的接口

| 角色 | 需提供/必须对接的接口 | 说明 |
|------|----------------------|------|
| **SIP 平台/后端** | 国标 INVITE 时调用 `openRtpServer(stream_id, ssrc, tcp_mode)` 并返回端口给设备；`on_publish` 鉴权放行；离线时 `closeRtpServer` | 决定"哪路国标流进来" |
| **后端** | 设备→流映射（`deviceId → live/{channelId}`）；`stream_url` 写入布控 | 分析器/布控引用该 URL |
| **分析器** | 按 `live/{channelId}` 拉流（与现有 RTSP 拉流一致） | 无需感知国标/RTSP 区别 |
| **前端** | 用 `ws://.../live/{id}.live.flv` 播放 | flv.js 或等效 |

## 6. 待办 / 风险（流媒体角色需知）

1. **WVP on_publish 鉴权流 id 时序**：P0 实测 `VMP_RTP_AUTHENTICATE:<流id>` 未写入 → 鉴权拒绝。用**真实设备 + 正确 RTP/SSRC 模式**或对齐 `refreshAuthenticateInfo` 时序后放行。
2. **媒体格式**：GB28181 设备推的是 **PS over RTP**（不是 TS）。ZLM 只认 PS（`GB28181Process`）。若用 ffmpeg 自建测试源，需 PS 封装（已备 `ps_rtp.py`）。
3. **NAT/可达**：设备的 RTP 回流地址与 ZLM `sdp-ip/stream-ip` 需一致；跨网段用公网 IP。
4. **TS vs PS**：`rtp_mpegts` 不可用，必须 PS。

## 7. 验证标准（流媒体接入是否成功）

1. 设备注册后，点播 → **ZLM `getMediaInfo(live/{channelId})` 返回 code=0**（流上线）。
2. `rtsp://zlm:9994/live/{channelId}` 可拉流（ffmpeg 拉到帧）。
3. 后端收到 `on_publish`/`on_stream_changed`，设备状态=在线；`on_rtp_server_timeout`/离线 → 离线。

## ✅ 端到端打通（2026-09-03 实测）

**结果**：`国标设备(模拟)→WVP(SIP)→INVITE→PS/RTP→生产ZLM→rtp/{设备_通道}→rtsp/flv 可播` 全链路成功。
- WVP 点播返回播放地址：`http://{zlm}:9992/rtp/{设备_通道}.live.flv`
- 生产 ZLM 注册出流：`rtp/34020000001320000001_34020000002320000001`（ts/rtsp/rtmp/fmp4）
- `getMediaList` 可见、`ffmpeg` 拉到 77 帧
- WVP 日志：`[ZLM HOOK]推流鉴权-允许-响应`（不再 auth failed）

**两处关键修复（WVP↔ZLM 集成）**：
1. **mediaServer 服务器 id 必须匹配**：WVP `media.id` 必须 = ZLM `[general] mediaServerId`（此处 `Aodpt9CbTmrRBOMv`），否则 WVP on_publish 报"找不到对应的mediaServer"。
2. **WVP 放行国标 RTP 流**：`MediaServiceImpl.authenticatePublish` 对 `app=rtp` 在鉴权键未命中时**默认放行**（这些流由 WVP 经 openRtpServer 管理，避免 60s TTL/stream-id 时序拒流）。

**生产写入：SVA-mediaServer 未改源码**（GB28181Process 原生支持），仅 WVP 配置/补丁 + 模拟器推流。
