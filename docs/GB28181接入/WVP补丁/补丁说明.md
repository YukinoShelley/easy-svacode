# WVP 补丁说明（让 GB28181 国标 RTP 流真正放行）

> 背景：WVP 的 `on_publish`（鉴权 hook）对国标 RTP 流返回 `auth failed`，导致 ZLM 拒收国标流。
> 根因：① WVP `media.id` ≠ ZLM `[general] mediaServerId` → WVP 报"找不到 mediaServer"；② `authenticatePublish` 对 `app=rtp` 依赖 60s TTL 的鉴权键，stream-id 时序可能未命中 → 拒流。

## 改动
文件：`MediaServiceImpl.java` → `authenticatePublish(...)`

把 `app=rtp`（国标 RTP）分支改为：**优先用鉴权键校验；未命中时默认放行**（这些流由 WVP 经 `openRtpServer` 管理，不应因 60s TTL / stream-id 时序被拒）。

```java
if (MediaStreamUtil.RTP_APP.equals(app)) {
    ResultForOnPublish r = receiveRtpServerService.getAuthenticateInfo(stream);
    if (r != null) { return r; }
    ResultForOnPublish def = new ResultForOnPublish();
    def.setEnable_mp4(userSetting.getRecordPushLive());
    def.setEnable_audio(true);
    return def;
}
```

## 另一处必改：WVP media.id 与 ZLM mediaServerId 一致
- ZLM 配置：`[general] mediaServerId=Aodpt9CbTmrRBOMv`（以实际为准）
- WVP 配置（`application-dev.yml` 的 `media.id`）：**必须等于它**，否则 WVP on_publish 报"找不到对应的mediaServer"。

## 效果
- 国标设备（模拟/真实）注册、点播后，ZLM 正常出流（rtp/{设备_通道}），rtsp/flv 可播。
- WVP 日志：`[ZLM HOOK]推流鉴权-允许-响应`。
