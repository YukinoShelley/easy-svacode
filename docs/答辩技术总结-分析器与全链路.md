## 二、技术方案与系统数据流

```
[RTSP 设备/GB28181 国标设备]
   │(GB:SIP注册5060 → INVITE → ZLM openRtpServer 收 PS-over-RTP)
   ▼
SVA-mediaServer(ZLMediaKit 9992/9994/9995)  ← 分发 rtsp/ws-flv
   ▼
SVA-server 分析器(9993,Worker 模型)
   ├─ AvPullStream:FFmpeg 拉流(rtsp/http/hls 通用,编解码自动协商)
   ├─ 解码→BGR→(按 detectFps 抽帧)→ 推理
   │     └─ on_yolo11n_pose:YOLO-Pose(640 letterbox 灰114,RBG)输出 1×56×8400
   │         = 4框 + 1 person 分 + 17关键点×3(x,y,conf)
   ├─ IoU 追踪(trackId/speed/motionState/regionStates 复用平台)
   ├─ BehaviorEvaluator:规则命中(睡岗=sleep 规则增强:关键点可用时 hd 判据)
   └─ 告警复用:截图/录像 → WS detect.event → 后端 h_waring → 截图回写
   ▼
SVA-backend(9114,若依):设备/布控/告警/国标同步(device_type 分流 buildStreamUrl)
   ▼
SVA-web:设备管理(类型区分/同步)/布控(睡岗可选)/告警(睡岗告警)
```

**关键工程决策(答辩可讲)**:
1. **模型契约对齐**(与 AI 角色):code=`on_yolo11n_pose`、模型 `yolo11n-pose.onnx`、letterbox 灰边114 居中、RGB、640;输出 channel-major(1,56,8400)——与 ultralytics Pose 头(kpt_shape=(17,3))一致;
2. **规则语义**:事件类型沿用平台 `sleep`(后端白名单放行→`SVA_SLEEP/睡岗告警`),姿态判据为 **hd 头肩比 ≤ 阈值**(默认 0.12,规则字段 `hdThreshold`,别名 thetaHd/theta_hd),持续时长 `thresholdMs`(演示 2000/真实建议 8000);关键点不可用时回退原"横躺宽高比"判据——**向后兼容,不破坏旧规则**;
3. **健壮性**:模型加载 try/catch(缺模型仅告警,睡岗任务按"不支持的算法"跳过,分析器照常服务)——该兜底是我在整合时补入 algorithm 引擎的;
4. **零新增 HTTP 路由**:全部复用 `/api/control/add|cancel|health|controls` 与告警上下行通道,只扩展字段/语义。

## 三、分析器侧代码层技术要点(以主干 algorithm 引擎为准)

| 模块 | 技术点 |
|---|---|
| 引擎初始化 `Scheduler::initAlgorithm` | 三段式:yolo11n.onnx / yolo26s.onnx / **yolo11n-pose.onnx**(睡岗,可选,缺模型 try/catch) |
| 解码 `AlgorithmOnYolo` | 新增 `Pose` 解码分支:输出 (1,56,8400) channel-major;关键点按 letterbox 逆映射 (x-pad)/scale 回源图;conf 0.25/NMS 0.5/kpt 可见 0.30 |
| 姿态字段 `DetectObject` | keypoints(17,cv::Point2f)+ keypointConf + hd(头肩比)+ poseOk |
| 规则 `BehaviorEvaluator` | `isSleepHit(controlCode,rule,detect,region)`:poseCapable 时 hd≤θ 状态机(连续低头 C1、滑窗 C2、趴桌 C3),legacy 回退 |
| 规则参数 `Control.h` | `hdThreshold`(解析 hdThreshold/thetaHd/theta_hd,默认 0.12) |
| 后端桥接 | HWaringController:`sleep` 白名单放行 → SVA_SLEEP/"睡岗告警"(告警名不被 customEventName 覆盖) |
| 数据契约 | h_device.device_type(RTSP/GB28181)、av_algorithm 种子 `on_yolopose_sleep`(睡岗检测(姿态关键点),id=19)、params_json 透传 |

> 说明:我曾独立实现一套纯增量姿态引擎(A1~A8:自定义关键点结构/俯角/hd 双指标/逐 track 时序历史/骨架可视化/模型别名兼容/缺模型兜底,提交在 `analyzer-integration` 分支),后按团队裁定"以算法分支为主干",将其收敛为文档/脚本/兜底增强并入主干;历史实现保留备查——这是"多实现融合取舍"的真实工程案例,答辩可讲。

## 四、测试与模拟脚本(用法 + 实测结果)——答辩重点演示素材

### 1) 模型一键接入 `scripts/install_pose_model.sh`
```bash
sudo bash scripts/install_pose_model.sh /path/yolo11n-pose.onnx   # 文件或目录
# 自动:校验→复制到 /opt/SVA/models/yolo11n-pose.onnx→重启分析器→验证日志
# 验证输出:health HTTP 200 + "初始化 on_yolo11n_pose" + decoder=pose(56ch) preprocess=letterbox_gray114_rgb + Start Success
```
**实测**:官方预训练版与段鹏鹏特调版(桌面交付,md5=4872aa85…)均一键接入成功;特调版 python 直测 28 person、装载+推理冒烟通过。

### 2) 睡岗联调 `scripts/sleep_post_test.sh`
```bash
DURATION_MS=5000 HD_RATIO=0.12 bash scripts/sleep_post_test.sh 睡岗样本.mp4
# 流程:推流(ZLM)→ 建布控(pose+sleep规则)→ 观察 detectFrameSent/上报次数 → 自动清理
```
**实测**:CCTV HLS 流、本地人物循环流均可拉流检测;规则解析/运行无错;触发正反例待正式样本。

### 3) GB28181 媒体收流自证 `tools/gb28181/verify_zlm_gb28181.sh`
```bash
cd tools/gb28181 && bash verify_zlm_gb28181.sh
# 原理:临时 ZLM(hook关)→ openRtpServer(port=0,stream_id=gbvtest)→ ffmpeg产PS | ps_rtp.py 打RTP
#       → getMediaInfo(app=rtp) code=0 → RTSP 拉流验证
```
**实测输出**:收流端口=41238;code=0 alive=3 track数=2;ffmpeg 拉流成功;**✅ PASS**(无需真机/摄像头)。

### 4) RTP 打包 `tools/gb28181/ps_rtp.py`
stdin 读 MPEG-PS → 切 1350B 负载 → RTP(PT96、可指定 ssrc)发到 ip:port——与 ffmpeg `-f vob` 管道组合模拟国标设备媒体面。

### 5) 最小 GB28181 SIP 平台/模拟设备(我编写,验收点3 全链演示)
```bash
# 平台(UDP 5060 注册/保活/INVITE点播/离线判定 + 控制口 18081)
python3 tools/gb28181/mini_gb28181_platform.py --offline-after 25
# 模拟国标设备(REGISTER/MESSAGE保活/应答INVITE后 ffmpeg→ps_rtp 推流)
PATH=/usr/local/ffmpeg/bin:$PATH python3 tools/gb28181/mini_gb28181_device.py \
    34020000001320000001 127.0.0.1:5060 /opt/testvideo.mp4 --loop
# 控制:注册状态 / 点播
curl http://127.0.0.1:18081/status          # devices[].online=true
curl http://127.0.0.1:18081/play/34020000001320000001   # INVITE → ZLM live/{gb_id} 出流
```
**实测**:SIP REGISTER 成功(平台 status 显示 online);点播链路脚本就绪(出流验证待续跑)。
> 局限:未实现 digest 认证(域无密码直通),生产用 WVP(wvp-GB28181-pro),仓库含其配置模板与放行补丁。

### 6) 推流素材(网页/布控联调用)
