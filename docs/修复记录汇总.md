## 二、源码修改明细（SVA-backend）

### 1. DeploymentController.java — 新增 live-output 接口

- **文件**：`SVA-backend/ruoyi-admin/src/main/java/com/ruoyi/web/controller/deployment/DeploymentController.java`
- **位置**：`stop` 方法与 `get` 方法之间
- **差异**：+22 行（git diff 与 Gitee 对比的唯一新增代码）
- **背景**：前端（Gitee 原版）已实现 `POST /deployments/{id}/live-output` 调用（`src/api/deployment.js` + `add.vue:1518`、`index.vue:264`、`center-switch-panel.vue:314`），后端缺对应路由，请求命中 Spring 静态资源兜底报错。本修改补齐该接口，返回算法画框输出流地址。

新增方法完整代码：

```java
    @PostMapping("/{id}/live-output")
    public AjaxResult liveOutput(@PathVariable("id") String id)
    {
        DeploymentTask record = deploymentTaskService.selectDeploymentTaskById(id);
        if (record == null)
        {
            return AjaxResult.error("布控任务不存在");
        }

        String algorithmStreamUrl =
            deploymentAnalyzerClient.buildAlgorithmStreamUrl(record.getDeviceId(), id);
        if (StringUtils.isEmpty(algorithmStreamUrl))
        {
            return AjaxResult.error("未绑定可用ZLM/SVA服务器或配置缺失，无法生成算法输出流地址");
        }

        Map<String, Object> data = new LinkedHashMap<>();
        data.put("algorithmStreamUrl", algorithmStreamUrl);
        data.put("algorithm_stream_url", algorithmStreamUrl);
        return AjaxResult.success(data);
    }
```

说明：

- 复用 `DeploymentAnalyzerClient.buildAlgorithmStreamUrl(apeId, deploymentId)`（该文件第 283 行），与 create/update 生成地址逻辑一致，输出 `ws://{zlmHost}:{zlmMediaHttpPort}/{svaApp}/{deploymentId}.live.flv`；
- 同时返回 `algorithmStreamUrl` 与 `algorithm_stream_url`，兼容前端两种取值；
- 无新增 import（`PostMapping`、`PathVariable`、`AjaxResult`、`StringUtils`、`Map`、`LinkedHashMap` 文件头均已存在）。

## 四、初始分卷压缩包（Analyzer-lib_zip.part*.rar）解压与安装

> 前置：分卷压缩包已下载到本机 `/home/jun/下载/`（3 个分卷：`Analyzer-lib_zip.part1.rar` 2GB、`part2.rar` 2GB、`part3.rar` 465MB，合计约 4.76GB）。分卷包内是 4.76GB 的 `Analyzer-lib.zip`（即 README 所述 easySVA-lib 依赖包，含 YOLO 模型与全部编译依赖），后续步骤从解压开始。

### 1. 确认分卷完整

```bash
ls -l /home/jun/下载/Analyzer-lib_zip.part*.rar
# 应有 3 个分卷：part1.rar（2GB）、part2.rar（2GB）、part3.rar（465MB）
# 缺一个分卷都无法解压
```

### 2. 解压分卷 RAR（得到 Analyzer-lib.zip）

```bash
cd /home/jun/下载
unrar x Analyzer-lib_zip.part1.rar    # 只需指定 part1，unrar 自动读取后续分卷
# 解出：Analyzer-lib.zip（约 4.76GB）
```

### 3. 放置到 /opt（脚本要求 install_source.sh 与依赖包都在 /opt）

```bash
sudo cp /home/jun/下载/Analyzer-lib.zip /opt/
sudo cp /home/jun/桌面/easySVA/easySVA/install_source.sh /opt/
```

### 4. 解压 zip 并核对目录名

```bash
cd /opt && sudo unzip Analyzer-lib.zip
# 解出 /opt/Analyzer-lib/；脚本写死 cd /opt/easySVA-lib，需改名：
sudo mv /opt/Analyzer-lib /opt/easySVA-lib
ls /opt/easySVA-lib/
```

### 5. 核对包内内容（脚本编译依赖这些文件）

```
models/                                   # yolo11n.onnx / yolo26s.onnx / yolo26s_miner.onnx / yolo26s_miner.yaml
ffmpeg-6.1.4.tar.xz
opencv-4.13.0.zip / opencv_contrib-4.13.0.zip
onnxruntime-linux-x64-1.26.0.tgz                          # CPU 版用
onnxruntime-linux-x64-gpu_cuda13-1.26.0.tgz               # GPU 版用
nv-codec-headers.zip / curl-7.83.0.zip
cuda_13.1.2_590.48.01_linux.run                           # GPU 版用（约 4.3GB）
llama.cpp-minicpm-omni.zip / 编译第三方库.md
```

### 6. 执行安装

```bash
cd /opt && sudo -s        # 脚本要求 root
./install_source.sh       # 过程中选择 GPU(G) / CPU(C) 版本
```

要点：分卷缺一不可；`unrar` 只需指定 part1；解压后先 `ls` 核对目录名（`easySVA-lib`）与内容再跑脚本，避免脚本 `cd /opt/easySVA-lib` 失败。
